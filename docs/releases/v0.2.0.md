# Spectrum Krea 2 v0.2.0 — experimental sampler and patch interoperability

This prerelease extends Spectrum feature forecasting for native ComfyUI Krea 2 RAW and Turbo. It is intended for controlled checkpoint/CUDA image-quality and performance evaluation. Unsupported or changed execution contracts retain native sampling.

## Changes since v0.1.0

- Added source-audited native forecasting paths for RES Multistep, Gradient Estimation, DEIS, iPNDM, iPNDM-V, stochastic/ODE ER-SDE, and SA-Solver (including predictor/corrector-aware PECE), alongside Euler and DPM++ 2M. Unreviewed solver options still fall back natively.
- Added qualified interoperability with Sol-Krea2 attention and Krea 2 Diff-Aid (text residual, values-only, keys-and-values). Patch-owner, config, attention-route and conditioning identities are rechecked during execution; changes cannot silently reuse incompatible feature history.
- Tracks Diff-Aid's effective gain per sampler call, including hard/partial/ramped sigma windows, and invalidates prior anchors when the gain changes. Session reports include bounded `diffaid_gains` traces. The companion Diff-Aid `sigma_reference=model_sigma_max` option can eliminate within-pass window transitions, but independently changes modulation and must be compared at matched seeds.
- Separates native SA-Solver Adams/corrector state from ephemeral forecast endpoints. PECE policies `stable_start`, `balanced`, `max_speed`, and `balanced_detail` are experimental; the default `off` remains the baseline.
- Adds invocation-scoped `FORCE_NATIVE_ALL_SAMPLERS` for planner-only quality isolation, including ER-SDE and Euler. The pre-existing `FORCE_NATIVE` continues to apply only to SA-Solver. Both scopes restore their previous value on exit.
- Adds short partial-denoise regression coverage, split-CFG attention-route isolation, native-only parity, callback/exception cleanup, forecast guard boundaries, detailed fallback reasons and build validation.

## Installation and companions

Install or update this repository through **ComfyUI Patcher** and restart ComfyUI. The Spectrum PR #2 changes are included in this release; **do not apply PR #2 on top of v0.2.0**.

Sol-Krea2 support was introduced by [Sol-H3 PR #44](https://github.com/xmarre/ComfyUI-Sol-H3/pull/44), which is merged. Krea 2 Diff-Aid requires the [Diff-Aid PR #12](https://github.com/xmarre/ComfyUI-DiffAid-Patches/pull/12) overlay until that PR is merged. Planner-only native controls in the companion Scale-Locked sampler require [Scale-Locked PR #22](https://github.com/xmarre/ComfyUI-ScaleLockedResidualDiffusion/pull/22), stacked on PR #21. These external patches are optional; the base Krea 2 workflow does not require them.

The default Sol `dense_evaluations=1` can consume the only eligible forecast in a four-step high-resolution stage. Changing it to zero changes the attention operator from the first evaluation, and may change image quality. Short stages also restart Spectrum history. No incompatible Diff-Aid gain or attention route may share forecast anchors.

## Limits and acceptance

**No real Krea 2 checkpoint CUDA quality or performance validation is established.** CPU scheduling, bitwise native/all-actual parity on small weights and counts of forecasts do not establish decoded image fidelity, attention-kernel correctness, peak VRAM or acceleration.

Use matched seeds to isolate changes. For Diff-Aid partial windows compare (a) `schedule_start` with Spectrum off, (b) `model_sigma_max` with Spectrum off, and (c) `model_sigma_max` with Spectrum on. Keep `sa_pece_forecast_policy=off` for baseline comparisons. Follow the [GPU validation protocol](../GPU_VALIDATION.md) before recommending accelerated defaults for production.
